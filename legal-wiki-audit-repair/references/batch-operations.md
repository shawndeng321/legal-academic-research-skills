# Wiki 批量操作：重命名、重编号、链接迁移、反向链接、批量填充

对 Obsidian/Markdown 研究库做**批量结构性操作**的安全流程。这类操作一次失误就可能造成全库死链或文件丢失。完成后必须按 `SKILL.md` 第十节做全量验收。链接规则的完整说明见 `legal-research-wiki` 的 `references/linking-and-cross-references.md`。

## 适用情形

- 按编号重命名案例文件、调整编号；注意：用户要的通常是**文件名**编号（`案例N-YYYY-标题.md`），不是在页面标题里加编号；
- 把实体页分到几个子文件夹（按层级、用途或优先级）；
- 全库链接跟随新文件名；
- 批量补反向链接、批量填充页面、批量插入章节或 YAML 字段；
- 论文页 ↔ 案例页关联的镜像同步、纯链接核验、规范依据小节插入。

## 通用纪律

1. **映射与备份放在 vault 内**：`.maintenance/<任务名>-<日期>/` 保存映射、备份（`before/`）和证据；不要只放系统临时目录，临时目录会被清理；
2. **先试运行**：写入脚本一律先 `--dry-run`（或 `DRY_RUN=1`），核对报告后再正式运行；
3. **范围冻结**：超过 10 页先列清单并取得确认；只改清单内的行或章节，不整段重写页面（并行会话可能在改同页其他行）；
4. **脚本写成文件再运行**；长中文映射表不要放在 heredoc 里；
5. **写后逐页复核**，不以脚本退出码或子代理报告代替。

## 一、重命名与重编号

1. **建映射** `旧文件名 → 新文件名`，校验：新旧名无重复、无缺失、编号连续；**标出 old == new 的项**；
2. **备份**全部涉及文件；
3. **执行**：old != new 时写新文件 → 校验 → 删旧文件；**old == new 时只更新内容，绝不删除**（“写新再删旧”会把同名文件删掉）；
4. **全库链接替换**：Obsidian 按文件名全局解析链接。移动到子文件夹**不需要改链接**；重命名**必须全库替换**，覆盖 `[[旧]]`、`[[旧|别名]]`、`[[旧\|别名]]`、`[[旧.md]]` 和历史遗留的 `[[旧&#124;别名]]`；
5. **验收**：全库 `rglob('*.md')` 提取链接，与页面 stem 集合比对，死链为零；检查错误模式残留（见下）和截断链接。

### 从文件名取编号必须用正则

中文文件名不能用字符切片（`stem[3:]` 会错位，拼出 `[[案例13-3-标题]]` 之类的假链接）：

```python
m = re.match(r'^案例(\d+)-(.*)$', stem)
if m:
    n, rest = int(m.group(1)), m.group(2)
```

插入链接时直接使用完整 stem，不要拼接。验收时同时查两种切片错误：`\[\[案例\d+-\d+-`（多出数字）与 `\[\[案例\d+--`（双连字符）。

### 重编号后新写页面的链接

编号调整后再批量填充页面，容易按旧编号的记忆写链接。每次填充后：

1. 从真实文件名建索引 `real[n] = 完整 stem`；
2. 扫描新页面的 `[[案例N-…]]`：编号存在且标题一致 → 正确；编号存在但标题不符 → 编号已被别的案例占用；编号不存在 → 按标题关键词在索引中找候选；
3. 用“旧链接串 → 真实文件名”映射替换，复跑死链与错误模式检查。

## 二、反向链接批量补齐

1. 统计单向链接（a → b 存在、b → a 不存在）；
2. 在目标页的关联章节**末尾**追加条目，条目带理由；
3. **章节边界**：找到章节标题，再找下一个 `\n## ` 作为结束；无该章节时插在“相关概念”前或文末。边界算错会把后面的标题吞进链接（`[[目标## 相关概念`）；插入串自带结尾换行；
4. **去重**：追加前检查章节中是否已有该目标；
5. **排除自链接**：跳过目标等于当前页面的条目。曾因此给数十个页面插入了指向自身、描述却属于别的案例的错位条目；清理用 `^- \[\[(<自身stem>)(?:\|[^\]]*)?\]\][^\n]*\n?`；
6. **变体标题**：章节名可能有变体（如“与某某底稿的关联”），用包含判断定位；
7. **中心节点**：所有案例页都有“与底稿的关联”后，底稿页可加一个反向导航章节，按分组列出全部案例链接；这类索引式章节没有编号条目，同步脚本应识别并跳过；
8. 补完后复跑：单向为零、死链为零。

## 三、批量填充：材料决定深度

填充深度由原始材料决定，不凭空补写裁判理由：

| 材料 | 页面深度 |
|---|---|
| 判决书全文、公报案例全文 | 详细页，各章节齐全 |
| 典型案例（中等篇幅） | 中等页 |
| 极简案例摘要 | 如实简写，注明材料性质 |

## 四、叙述中的案例提及也要链接

比较页、综合页正文里提到的案例名也要加链接，用显示名保持可读：正文 `[[案例文件名|简称案]]`，表格 `[[案例文件名\|简称案]]`。

- 先建“提及词 → (完整文件名, 显示名)”映射，长提及词先替换，避免子串冲突；
- 已含 `[[` 的文本跳过，防止嵌套；
- 验收：把页面中所有 `[[…]]` 替换为占位符后，扫描剩余的“某某案”模式（排除“本案、案件、案例、案由”等通用词）。

### 表格中的别名链接

表格单元格里写 `[[目标|别名]]` 时，`|` 会被当成列分隔符，整行错位。**用 `[[目标\|别名]]`**：Obsidian 能识别转义管道符为别名分隔符，表格也不会被拆列。不要用 `&#124;`：Obsidian 不把它当分隔符，会形成死链和带 `&` 的空白节点。验收：统计每张表各行列数前先去掉 `\|`，列数不齐为零。

## 五、用户初稿引用的案例

用户提供“初稿引用的 N 个案例”材料时，**先勘察再摄入**：用“当事人 + 诉 + 机关”等关键词把每个案例映射到库内编号；全部已在库中时告知用户无需摄入，只做增量工作：

- 建导航页 `queries/初稿引用案例.md`：案例链接、核心争点、层级；**不写脚注编号**，注明“脚注以初稿实际编号为准”；
- 汇编材料中的“对应论文脚注”只是整理者的标注，论文正文未入库前，**不在案例页添加论文脚注章节**；
- 材料中有完整案号而库内页面缺案号时，可补基本信息。

## 六、论文页 ↔ 案例页关联的批量操作

关联的建立标准（引用轨 + 主旨轨、无实质对应不硬加）见 `legal-research-wiki` 的链接参考文件。批量执行时：

### 1. 插入“与案例的关联”章节

- 数据源：论文编号论点索引（键 = 论文文件名）与案例裁判要旨索引（键 = 案例完整文件名，含年份），放在 `.maintenance/` 下；
- 先通读要旨再逐篇匹配，**严格基于要旨文本**；可用论文页自身的“引用案例”章节交叉验证；
- 制度构建、立法论类论文先找间接对应（例如制度设计对应的救济、追偿、协议效力类案例），穷尽后才写“与个案要旨直接对应较少”；
- 要旨为空的案例，从案例页“裁判理由”“程序历程”章节提取主旨再匹配，不要跳过；
- 问题式要旨（只写争议问题、没有裁判规则句）按争议主题匹配论文观点；反衬关系在理由中写明“反衬”；
- **泛观点膨胀控制**：“倾斜保护”一类总原则观点几乎能配所有案例，只保留紧密对应；同一论文同一观点对应多个案例时合并为一条；
- 论文聚焦某类判决（如撤销重作判决）时，要旨不足为凭，回读程序历程核实法院是否真的作出了该类判决；
- 验收用 `scripts/verify_case_link_sections.py`（章节位置、链接目标存在、理由长度、说明行）。

### 2. 纯链接核验（旧“相关论文”章节）

早期按主题相似批量生成的纯链接，真实率可能只有三成左右，**核验前不假定为真**：

1. 案例页同时有“与论文的关联”（带理由）和旧“相关论文”（纯链接）时，先把旧链接并入新章节并去重，删除旧章节；
2. 建核验清单（案例、论文、页面），分批处理；决策表 `D = {序号: ('keep', 理由) | ('delete',)}`，断言覆盖清单区间；
3. 逐对判断“案例要旨 ↔ 论文核心论点”是否真有印证、支撑或反衬，同主题泛泛不算。**按论文类型定宽严**：只把真正讨论某问题的案例配给研究该问题的论文；判决结果对某方有利、或某类判决只是常规结果，不构成印证；论文研究对象就是本案时必须保留；
4. 保留的替换为带理由条目（观点编号取自论点索引，定不了编号就写“本文观点”）；删除的整行删去；
5. 每条删除附一句理由写进报告；保留项再反向同步到论文页（下一节）。

### 3. 案例页 → 论文页同步

`scripts/scan_missing_paper_case_links.py <wiki> <论文stem…> [--plan 文件]` 递归报告缺漏；
`scripts/sync_paper_case_links.py <wiki> --plan 文件 [--dry-run]` 执行追加。**TARGETS 已移出源码**：
每批论文清单写在 plan JSON（`{"papers": [{"key": "作者-论文题名", "file": "…md", "expect_sha256": "可选"}]}`，
也可用映射简写），运行任务不再修改技能文件。

- 章节提取统一（`scripts/case_link_utils.py`，几个脚本共用）：支持文末章节、空章节、
  `[[ ]]` 与无链接两种写法、别名（含 `\|`）与中英文冒号；
- 按论文**完整文件名**匹配（整名匹配），同一作者多篇论文不能用作者名前缀；
- 去重按论文页章节内全部链接的 stem 集合（一条可含多个案例）；关系类型
  （支持／反驳／边界例／引用）自案例页条目“——”前的连接语分类并分开统计；
- 编号接续**写入时**章节内最大编号；插在章节最后一个非空行之后，保留其后的空行结构；
- 预演输出**具体 diff**、将追加条目与文件哈希；plan 可带 `expect_sha256`（取预演输出），
  冲突时停止并重新预演；
- 批次内完成 备份 → 修改 → 更新 `updated` → 追加 `log.md` → 写后逐页复核；
  部分失败时报告已改与未改范围（备份可恢复）；
- 理由沿用案例页条目，必要时调整为论文视角；理由 60-150 字按统一 CJK 口径计
  （`case_link_utils.cjk_len`，与验收脚本同一函数）；
- 父任务指定由其他批次处理的论文不编辑，只报告缺失数；
- 因去重规则造成的单向关联属预期时，列入白名单并在报告中说明；
- 验收：`verify_case_link_sections.py`（章节位置、链接目标存在含别名写法、理由长度、
  说明行、关系分布）；做**逐对双向校验**，并抽查被修改文件尾部章节未被吞掉。

### 4. 概念页“规范依据”小节

`scripts/insert_norm_sections.py <wiki> --plan 文件 [--dry-run]`：plan JSON 写
`{"pages": {"concepts/某概念.md": [["法规范页文件名", "说明"], …]}}`，每页 2—4 条；**PLAN 已移出源码**。
插在“与比较页的关联”之前（没有则在“相关概念”之前）；说明 30—80 字（CJK 口径，与论文—案例
脚本共用同一函数），写明哪些条文支撑本概念；链接目标必须存在于 `entities/法规范/`（递归）；
已有该小节的页面跳过（幂等）；预演输出具体 diff；写入批次含 备份 → 修改 → 更新 `updated` →
追加 `log.md` → 复核。法规范页摘要索引可能被截断，具体条文要读真实页面核实。

## 七、YAML 字段批量插入

例如给全部案例页加 `usage: 详析/脚注/备用`：

1. 映射写成脚本中的字典（编号 → 值）；
2. 锚定 `type:` 行插入：`re.sub(r"^(type: case)$", r"\1\nusage: " + value, text, count=1, flags=re.M)`；已有该字段的页面跳过并报告；
3. 插入前逐文件备份；
4. 验收：分布计数与预期一致，每页恰好一个合法值，文件仍以 `---` 开头；
5. 配套清单页（如 `queries/案例选用清单.md`）中的每个链接都真实存在。

## 八、批量操作后的格式审计

**修复规则**：

1. YAML `title` 与页面一级标题统一，以页面标题为准；标题含中文引号时不要再用英文双引号包裹；
2. 批量补“标题后空行”时跳过代码块、表格行；
3. 审计脚本先自检：计数突然异常（如 YAML 错误从 0 变成上百）先怀疑脚本本身，用最小样本人工核对。

**误报甄别**：

- `SCHEMA.md`、`log.md`、台账、`index.md` 没有 frontmatter、标题后无空行属正常；
- 检察指导性案例等本体页使用变体章节名，不是缺章节；
- 路径、来源说明、外国判例引注、DOI 中的英文是有意内容；
- 维护文档中带省略号的示例链接是示例文字。

## 九、环境陷阱

- 子目录可能被加了数字前缀（`1. 核心案例`）；路径报错时先列目录；
- 按效力层级重排法规范子目录时直接移动目录，链接不受影响，旧路径只残留在日志历史中；
- 某些宿主的读文件工具会把中文密集的 Markdown 误判为二进制或缓存旧内容；用 Python 以 UTF-8 读写真实文件；
- 某些宿主会拦截内联代码执行，改为把脚本写成文件再运行。
