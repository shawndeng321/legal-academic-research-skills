# 同批最终状态验收

仅用于知识库摄入、关联与库审计；不合并论文改稿轮次，不改变写作交接、来源核验或必要独立复核。稿件版本同步仍按原专门流程执行。

1. 按已授权范围完成备份、试运行、页面修改和逐页回读，再更新关联、index、日期、台账与日志。读真实日志末尾后追加，不覆盖别人的记录。
2. 最后一次写入后做完整最终验收：YAML、原始来源、死链、空目标、格式、关联及全部适用人工检查。日志可先记“待最终核验”；验收数字和证据先输出到库外报告，避免为回填数字反复改动被查文件。
3. 同一检查已覆盖相同最终状态时引用该结果，不重复扫描。须核对库根、检查器及版本/参数、文件路径集合与原始字节 SHA-256、时效日期和完整输出；mtime 或旧日志中的“通过”不足以复用。只读审计不因留痕创建文件。
4. 检查后改页面、索引、关联、台账或日志，旧结果相应失效。没有经过验证的影响范围机制就重跑该检查；最后一次日志/台账追加必须包含在最终死链扫描中。若最终全库扫描已覆盖此次追加，不再为了“写日志后检查”重复同一扫描。不能因日志禁止链接示例就假定日志没有坏链。
5. 机器结果只代表该工具覆盖范围；来源真实性、逐页回读、双向关系与学术判断继续分别验收。失败、未检查、人工待办保留，不能用复用制造“全部通过”。

## 可选的深检结果复用

按技能名找到 `legal-wiki-audit-repair` 的 `scripts/audit_snapshot.py`，不假定相邻安装。未安装时按上述规则做原有完整检查。该入口只封装七项深检，不能替代建库的 `check_wikilinks.py --strict`（含日志、台账等元文件）、原件哈希复核或人工验收。

```bash
AUDIT_SKILL='/实际安装位置/legal-wiki-audit-repair'
WIKI_PATH='/用户指定的知识库'
# 保存记录须有授权；父目录已存在、文件名未使用，且在知识库与技能目录之外。
python3 "$AUDIT_SKILL/scripts/audit_snapshot.py" "$WIKI_PATH" --strict --json --save-state '/库外证据目录/本批-final.json'
# 只读复核：内容与参数等完全一致时复用，否则自动全量重查。
python3 "$AUDIT_SKILL/scripts/audit_snapshot.py" "$WIKI_PATH" --strict --json --baseline '/库外证据目录/本批-final.json'
```

默认零写入；`--save-state` 是显式新建证据的操作，不覆盖已有文件。扫描失败、不可读文件、扫描期间文件变化时不保存可复用记录。记录损坏、检查器/选项/库根/日期或内容变化时不能沿用旧结论；无法建立可靠文件清单时明确未完成。`--force-full` 强制完整深检。JSON 的 `execution` 给出实际重查/复用组、失效原因及状态稳定性；结果为机器检查，不表示整批学术验收完成。
