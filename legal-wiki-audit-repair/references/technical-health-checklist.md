# 技术健康轨检查细则（目录、YAML、来源、链接、图谱、格式、脚本、统计）

> 由审计技能 SKILL.md 第四节迁出（WIKI-12 瘦身）；正文保留检查项一览，本文载判定细节与报告口径。

所有扫描必须**递归**：正式页面通常在 `entities/引用文献/`、`entities/案例/`、`entities/法规范/` 等嵌套目录中，并包括 vault 根目录；不用顶层 `glob('*.md')` 得出全库结论。

- **4.1 目录与页面清单**：统计各类页面、原始文件、空目录、根目录文件、隐藏文件和脚本；区分正式内容页、元文件（index、SCHEMA、log、台账）、0 字节幽灵页、系统文件（如 `.DS_Store`）、原始材料与中间产物。
- **4.2 YAML 与类型**：递归解析 frontmatter；检查缺失或错误、必需字段、`type` 与 SCHEMA 和目录的一致性、`title`/一级标题/文件名关系、`created`/`updated`、`confidence`/`contested`/`contradictions` 是否有区分作用、类型专属字段缺失。文件修改时间晚于 `updated` 只列待确认候选，不机械改日期。
- **4.3 来源与原始材料**：`sources:` 路径是否存在；非路径值（作者、目录、口述、Wiki 页面）不误报为“文件丢失”；原始材料是否至少被一个页面引用、是否有重复哈希；综合 3 个以上来源的页面是否有段落级或区块级出处；是否需要 `references`、`derived_from`、`source_note`、`corpus` 等字段分流。
- **4.4 链接与 index**：解析规则与 `legal-research-wiki` 共用（`scripts/wiki_links.py`）。分别报告：正式内容页真实死链与缺失附件（附件按全库文件名核对）；指向 0 字节页的“空目标”；同名歧义（不静默合并，单列）；显式路径前缀不符；标题/块锚点不存在（块锚点待核）；畸形写法（`&#124;`、嵌套方括号、吞标题、缺右括号、空链接目标）；`SCHEMA.md` 示例与 `log.md` 历史链接（误报单列）；index 缺页或多余。验收口径是“正式内容页死链为零”（`--strict` 下畸形、空目标、附件缺失、路径前缀、锚点缺失与同名歧义同为零）；`drafts/` 链接（包括初稿工作版的 `[[脚注N]]` 标记）为容忍类，单独报告、不“修复”。可运行 `legal-research-wiki` 的 `scripts/check_wikilinks.py <vault> --strict`。Obsidian 能打开 0 字节目标不代表链接健康。

  **Obsidian 真实解析规则**（别名拆分、`&#124;`、反引号示例、Graph 空白节点、畸形链接、幽灵文件复活、`.md` 后缀、案号全半角）见 [obsidian-parsing-details.md](obsidian-parsing-details.md)。
- **4.5 图谱与孤岛**：入站关系分导航入站（来自 index）与实质入站（来自其他正式内容页）；index 可达不等于知识相关。计算分类间边矩阵、出入站分布、孤岛与中心节点；检查是否为大量页面指向少数中心的星形结构。不为降低孤岛数而机械补链接；每条关系要能说明呼应、补充、分歧、规范要件、证明结构、程序阶段或时间演变。
- **4.6 标签、命名和格式**：标签是否在 SCHEMA 词表内、是否混用主题/要件/程序/来源/结果/研究用途；同义标签、层级缺失、自由标签扩散；重复 stem/标题、空格与异常标点；标题前后空行；PDF 残留、关键词换行、中文摘要夹英文；结论长度与碎片开头。超过 200 行的页面只列可读性候选，不机械拆分。论文页一次运行完整六维检查（摘要、结论、PDF 残留、关键词、YAML、标题空行），不修一项就宣布全库通过。
- **4.7 脚本与 Obsidian 配置**：审计生成脚本是否有绝对路径、过期输出目录、`open(..., 'w')` 直接覆盖、缺 `--dry-run`/不覆盖保护/备份/映射清单、固定模板；存在即标 P1，禁止直接运行。检查 `.obsidian/graph.json`、`app.json`、核心插件与新笔记默认位置；研究视图与质检视图分开（质检视图显示孤岛、未解析链接与方向箭头）。
- **4.8 研究设计与统计状态**：“统计口径可执行”≠“已计算”：核查数字是否真的算过、是否基于逐案文本归类、结果是否写入矩阵并更新研究假说状态；绝不编造数字。结果字段落地后机器全量重算与人工口径交叉核对，差异逐项归因，不直接改定稿数字。`methodology/` 页注明与某技能版本同步时，技能升级后同步其版本说明与新增规则。

**技术轨完成条件**：给出可复算的计数、具体路径和误报分类，而不是“结构良好”。

## 深检脚本 `multimodal_audit.py`

> 由审计技能 SKILL.md 第十一节迁出（v2610.17 精简）。

`scripts/multimodal_audit.py "<WIKI_PATH>" [--json] [--strict] [--privacy]`：七项全库深检——索引一致性、未摄入原始材料、frontmatter 质量、链接完整性、文件卫生与惯例、日志格式、法学专项（法规范时效、案件去重、隐私格式）。中文报告，每条发现含规则编号（IDX/RAW/FM/LINK/HYG/LOG/NORM/DUP/PRIV）、路径、定位、严重程度与检查范围；退出码 0=通过、1=存在阻断项（`--strict` 下提示项也计入）、2=执行失败或扫描不完整，未扫描到对象时不输出“通过”。需要 PyYAML（见 `requirements-dev.txt`）；链接解析与 `legal-research-wiki` 的 `check_wikilinks.py` 共用 `scripts/wiki_links.py`（两份字节一致）。已按法学库适配：页面以 vault 相对路径为身份、同名文件单独报告；默认扫描整个 `raw/`（含 `cases/`、`法规范/`），仅 `raw/transcripts`、`raw/screenshots` 强制同名提取；frontmatter 用真实 YAML 解析并检查字段类型、空值与重复键（解析失败单列）；标签词表兼容分类标题式 SCHEMA，只对单次使用且不在词表中的标签提示；跳过 `.maintenance`、`drafts`、`_scripts`、备份与隐藏目录（备份不得掩盖死链）；正式目录、排除目录、必填字段、`norm_verify_max_age_days` 与 `privacy{enabled, extra_patterns}` 可用 vault 根的 `wiki-audit.config.json` 覆盖（`--privacy` 启用可选隐私检查，命中值打码、只报告不改动）。不要用上游 multimodal-wiki 的脚本覆盖。
