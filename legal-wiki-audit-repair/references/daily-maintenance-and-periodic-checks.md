# 每日检修、迭代与通用巡检增强（细则）

> 由审计技能 SKILL.md 第十、十一节迁出（WIKI-12 瘦身）；触发条件与只读纪律保留在 SKILL.md。

## 一、每日检修

**触发**：用户说“今天检修”“每日检修”，或按既定计划执行。检修**默认只读（含日志）**：未获既定授权时不写任何文件，报告直接输出在会话中；发现问题按模式纪律提出方案。

**流程（约 10 分钟）**：

1. 定向：读 `log.md` 最近 30—80 行和台账最近三条执行记录；
2. 全库回归（一个脚本扫完）：页面总数与台账基线对比；frontmatter 缺失与 YAML 错误为零；正式页死链为零（含畸形链接）；标签全部在 SCHEMA 词表内；类型专属字段覆盖率；论文 ↔ 案例双向对称；法规范时效（缺 效力状态/核验日期、核验过期、失效规范被引用）与案件去重（案号规范化后重复）；原始材料哈希核验（见下）；
3. 对照台账最近的 OPT，检查验收缺口和未闭环事项；
4. 日志：默认只读——拟追加的当日记录（各计数与发现）先附在报告末尾；仅在**已有既定授权**（用户明确同意过每日检修写日志，或该惯例已记入交接页／台账）时才直接追加到 `log.md`。台账只在发生实际修改时追加；
5. 发现 P1 及以上问题 → 列修复方案，等用户确认（默认每批 5—8 页）。

每周至少运行一次深检脚本 `scripts/multimodal_audit.py`（加 `--strict` 时提示项也计入失败）：它能抓到轻量检修漏掉的畸形链接、空目标（0 字节页面）与同名歧义。

**迭代规则**：连续检修满 3 天后，依据最近 3 天的检修记录更新检修方法（检查项增减、回归脚本改进、新易错点、口径变化），结果写入台账规则回写区（候选 → 确认），并同步 `methodology/` 中的版本说明。某天漏检时，迭代顺延至补齐连续 3 天。

**常见易错点**：

- 终审日期要取裁判结果正文中的判决或裁定日期；基本信息末项的日期常是后续事件；
- 批量修正按编号前缀定位文件，不按全名匹配；
- 结果类别的边界（和解、撤回、检察监督后重新处理、民事与行政撤销的区别）写进口径清单；判断顺序要避免包含关系导致误判（例如“不予认定”中包含“认定”二字）；
- 正则在 `re.S` 下 `.*` 会贪婪吞到文件末尾，标题行匹配用 `[^\n]*`。

## 二、通用巡检增强

- **LOG-ROTATE**：`log.md` 超过 500 条 `## [YYYY-MM-DD]` 条目时轮转：改名为 `log-YYYY.md` 存档，新建 `log.md`（保留头部说明）。
- **SHA256-DRIFT**：`raw/` 下提取文件的 frontmatter 带 `text_sha256:`（或旧字段 `sha256:`）时，按统一口径重算正文哈希比对（口径见 `legal-research-wiki` 的 `references/multimodal-pdf-extraction.md` 第 0 节；一键只读复核 `scripts/batch_extract_papers.py <raw/papers> --verify`）；或把原始文件的大小与哈希集中记录在 `raw/MANIFEST.md` 的“机器核验指纹”一节，每日检修对照重算。批量漂移（10 个以上文件同时）优先怀疑系统性原因（占位哈希、行尾符、编码、批量清洗），先归因；单个漂移核对是否真实变更，确认后更新并记入台账；**真实漂移不自动重算覆盖**。摄入新材料更新 MANIFEST 时顺手计算哈希。法学库原始材料多为 DOCX/PDF，没有哈希字段不报错。
- **CONTESTED**：列出 frontmatter 中 `contested: true` 和 `contradictions:` 的页面供用户审阅。学术分歧正是适用场景：保留双方立场、日期和来源，不静默覆盖一方；提交论文前逐页核验是否已处理。
- **CLOSED-WORLD QUERY**：查询和写作支撑只用库内内容；库内没有的如实说明并标 `[来源不明]`，提供摄入方案；空壳页面不算覆盖；联网检索属于摄入环节；来源性主张必须能回溯到库内页面与原始材料。

## 三、延伸参考

- 用户环境中若已有自己的每日检修脚本，优先使用；没有时由本技能按需执行，或把等价脚本放入 vault 的 `_scripts/`，由用户用系统定时任务（cron、launchd、Windows 任务计划程序）运行。
- 在 Google Antigravity 环境中，可使用内置的 `schedule` 工具或建议用户输入 `/schedule` 命令配置周期性自动巡检任务；发现需要用户决策的问题时，调用 `ask_question` 交付结构化确认。
- 空壳来源补全：`references/multimodal-reingest-stubs.md`（补全属于摄入动作，查询阶段禁止补全）；哈希批量修复：`references/multimodal-sha256-bulk-fix.md`。

## 四、更新技能后的自测

修改本技能（或本技能包中的任何技能）后：

1. **仓库测试**：在技能包仓库根目录运行 `python3 -m unittest discover -s tests`（兼容性、脚本安全、Bundle 更新器），全部通过才算通过；
2. **宿主加载**：Hermes 用 `hermes skills list` 确认可见、版本正确；Claude Code 新建会话后确认技能出现在可用技能中（插件安装的运行 `/reload-plugins`）；Codex 新建任务后确认可按名称调用；
3. **真实知识库只读回归**：对一个真实 vault 跑全库体检，确认检查逻辑没有被改坏；
4. **小任务试跑**：用新版本执行一次每日检修等小任务，并按 `evals/pressure-tests.md` 抽测相关场景（修改了哪部分规则，就测哪部分）；
5. **闭世界验证**：审计结论全部能回溯到库内页面和原始材料。
