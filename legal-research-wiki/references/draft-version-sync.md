# 论文草稿版本同步：新版摄入与全库基准切换

触发：用户把论文的新版本放进 `drafts/`（常见三件套：净稿、修订标红版、修改说明），并要求“摄入知识库”。每出一个新版本都走完整清单：只把一个 Markdown 文件放进 `drafts/` 不算完成。

本流程发生在“论文定稿、回填知识库”这一步，见 `SKILL.md` 的“知识库与论文写作双轨隔离”。

## 0. 前置侦查

- 读交接页（`queries/` 下的会话交接任务书，若有）与 `log.md` 末尾：当前版本号、文件路径、读取顺序、最近的基线数字。
- 分清三件套的角色：净稿是提取源（含 `word/footnotes.xml`）；标红版用于可视化改动，一般不提取；修改说明是版本变更依据（含对照表，是写版本沿革与核对数字的底本）。
- 原件保持用户提供的文件名（包括下载产生的 “(1)” 后缀），不改名；只有被替代的旧版才加前缀。
- **旧稿保留**：按用户决定的保留窗口处理（例如只保留当前版与上一版）。更早的旧稿移出 `drafts/` 前，先归档到 `.maintenance/DELETE-drafts-pre<版本>-<日期>/`，不直接删除。

## 1. 净稿 → Markdown 工作版

- 用 zipfile 直接读取 `word/document.xml` 与 `word/footnotes.xml`（python-docx 不读脚注，见 [docx-footnote-extraction.md](docx-footnote-extraction.md)）。先统计 `w:ins`/`w:del` 修订数，应为 0；不为 0 时先剔除 `w:del` 内容再提取。
- 逐段读取 `<w:t>` 与 `<w:footnoteReference w:id>`：在引用位先插入不会与正文冲突的唯一占位符，再整体替换为工作版的脚注标记（形态与此前各版保持一致，见 docx-footnote-extraction.md 的“引用位自带方括号”）。
- 文末脚注表逐行 `[N] 文本`，剥掉脚注文本自带的 `[]` 前缀。
- 文件名沿用上一版的命名方式。
- 断言：引用数 = 脚注文本数 = 正文标记数 = 脚注表行数；抽查首段标题与文末结语存在。
- 修改说明也转为 Markdown 放入 `drafts/`：表格按 `w:tr`→`w:tc` 转为 Markdown 表（首行作表头；自动提取常把表格拍平）；标题“一、”→`##`、“（一）”→`###`。

## 2. 内容一致性核验

把修改说明中“原样保留”的声明变成已核验的事实：

- **案号集合**：新旧两版脚注各提取完整案号集合（`（20\d{2}）[^，。；]*?号`），核对是否与声明一致（例如“案例未动”时，旧版案号未减、新版未增）；
- **脚注算术**：原注数 + “参见前注”数 + 新增数 = 新版总数；
- **字数**：正文汉字计数与“约 N 万字”的声明相符。

## 3. 版本管理：全库引用一次切干净

1. 全库检索旧版的链接与“当前基准”表述：活文件（交接页、`index.md`、研究设计等）要改；`log.md` 与已废弃文件中的历史引用不动。
2. 旧版文件加 `废弃-` 前缀（`drafts/` 中的 md 与 docx、`queries/` 中的行文思路页等），与此前惯例一致。
3. 新建本版的行文思路页（`queries/`，模板见 `assets/templates/writing-outline.md`）：结构树、每节打法、关键设计对应表、版本沿革（最新一行在前）。用户未提供行文思路文件时，从净稿与修改说明整理，并在 `source_note` 注明来源。
4. 更新交接页：最新版本号、三件套路径、行文思路链接、题名与主线、版本沿革一行（谁批注、改了什么、什么未动）、“唯一正文基准”表述、读取顺序、文件地图、审稿反馈落实状态，以及修改说明中“待作者核补”的事项；`updated` 改为当天。
5. 在 `research-design/`、`methodology/`、`comparisons/`、`concepts/`、`queries/`、`index.md` 中检索旧版本号，逐处核对“当前基准”一类表述（最容易漏）。
6. `index.md`：头部计数用脚本实际统计后再写（旧数字可能本身有误）；`drafts/` 不计入正式页数；分区同步更新（旧版行文思路标为“存档，仅历史参考”）。

## 4. 备份与记录

- `.maintenance/DRAFT<版本>-<日期>/before/`：交接页、`index.md`、行文思路页、本次改动的研究设计页，以及 `renames.txt`（旧名 → 新名）。
- `log.md` 末尾追加一条（背景、摄入、版本管理、交接与方案同步、备份、验收）。条目中不写任何链接示例（自引用陷阱）；写完立即重跑死链扫描。

## 5. 验收

- `scripts/check_wikilinks.py --strict`：`drafts/` 中的脚注标记列为容忍类，不计死链；正式内容页死链与畸形链接必须为零。
- 新页名与加了 `废弃-` 前缀的旧页名，都不应出现在死链列表中。
- 新建与改动页面的 YAML 可解析。
- Obsidian：重命名前看一眼 `.obsidian/workspace.json` 的 `lastOpenFiles` 是否引用旧名；Obsidian 运行时不要编辑该文件（会被回写覆盖）；报告中提醒用户重启 Obsidian 刷新文件树。

## 6. 向用户报告

先回答“能看到新版本”，再用四点、大白话：（1）摄入了什么（新工作版、修改说明，原件未动）；（2）版本管理（废弃前缀、行文思路页、交接页与索引同步）；（3）核验数字（脚注、案号、死链）；（4）待办提醒（重启 Obsidian、修改说明中的待核事项）。不贴命令，不展开技术细节。
