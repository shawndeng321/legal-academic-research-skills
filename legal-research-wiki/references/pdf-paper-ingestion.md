# 学术论文 PDF 摄入与质量修复

用于把中文法学期刊论文（常见来源：知网等数据库下载的 PDF）批量摄入为 Wiki 论文实体页，并修复自动提取留下的缺陷。本文件合并了多轮实际建库中反复出现的问题；示例中的数字只说明量级，不是门槛。

## 一、提取前

1. **先盘点，不直接处理**：列出目录、计数、识别重复文件（`(1).pdf` 副本先用 `shasum -a 256` 或 `diff` 比对，报告给用户，不静默过滤）。
2. **文件名以磁盘为准**：数据库下载的中文文件名常含全角引号、破折号、冒号等 Unicode 标点，与用户或任务描述中的直引号写法不同。先列目录拿到真实文件名，再判断“缺失”。
3. **脚本写成文件再运行**：含中文路径、f-string 和 shell 引号的长命令容易出错；把提取脚本保存为 `.py` 再执行，临时文件放系统临时目录。
4. **工具选择**：文本型 PDF 用 `pymupdf` 即可（`scripts/batch_extract_papers.py`，先 `--dry-run`，已有 `.txt` 默认不覆盖，需要时显式 `--force`）；扫描版 PDF 没有文字层，直接让模型读页面图像并逐页转写，转写结果按原页码保存为 `.txt` 伴随文件；只有数百页以上的大批量扫描件，为节省成本才考虑专门的 OCR 工具，使用前先告知用户所需安装。
5. **读全文**：只读前若干页会漏掉结语；结论提取要覆盖全文。

## 二、结构化提取字段

每篇论文建议提取为结构化记录，再由主流程写页面：

`filename, title, author, affiliation, journal, year, issue, pages, doi, abstract, keywords, key_arguments(3—5条), methodology, conclusions, cases_cited, statutes_cited, concepts`

`cases_cited`、`statutes_cited`、`concepts` 是后续建立链接网络的原料，不要省略。

### 书目信息不可轻信自动提取

PDF 首页常见期刊页眉、栏目名、卷期号，自动提取会把它们误当标题或作者（例如把“某某学刊 2020 年第 X 期”识别成题名，把基金注释识别成作者）。做法：

- 建一张**人工校正表**（标题、作者、单位、期刊、年份、卷期、页码、DOI），以 PDF 首页和页脚印刷信息为准；用户按“标题_作者.pdf”命名的文件名可作参考，但仍需与首页核对；
- 自动提取只信任摘要、关键词、章节标题和法条等正文信息；
- 元数据仍不确定时，`confidence` 不要一律写 `high`。

## 三、常见提取缺陷与修复

| 缺陷 | 识别信号 | 修复 |
|---|---|---|
| 摘要混入英文 | 摘要段出现 `[A-Za-z]{10,}` | 从 PDF 取中文“摘要/内容提要”替换；双语 PDF 常见 |
| 全角英文摘要混入 | 行内全角 ASCII（U+FF01—U+FF5E）远多于汉字 | 按**行**删除全角英文占主导的行，不要逐字删除（会误伤夹有全角数字的中文） |
| 版面残留 | `［摘要］`/`【关键词】` 类标签、`［1］` 注码、`］［` 残片；`· 9 1 1 ·` 式页码、`瑏瑠` 等私用区字符、`〔1〕` 引注号 | 前三类运行 `scripts/clean_pdf_artifacts.py`（只处理论文页的摘要、关键词、核心论点、主要结论四个章节，其他章节和案例页的 `【裁判要旨】` 等标签不动；先 `--dry-run`，正式运行须 `--backup-dir`）；页码、私用区字符与 `〔1〕` 类残留脚本不处理，按下文“核心论点”一行重写 |
| 句中断行 | 中文标点后接单个换行 | 合并单换行、保留段落空行：`re.sub(r'([^\n])\n([^\n])', r'\1\2', text)`，只作用于摘要、结论等段落 |
| 页眉嵌入句中 | 句中出现“某某学刊 2020 年第 12 期”等 | 先按页眉模式删除，再做断行合并；顺序反了页眉会并入正文 |
| 关键词损坏 | 关键词段含换行或括号残留 | 去括号、合并换行、统一分隔符 |
| 核心论点是原文段落堆砌 | 含 `**一、……**` 等原文小节标题、页码、脚注号 | 不要逐处清理，按原文结构**重写**为 3—4 条编号论点，每条说明一个完整判断 |
| 结论取错位置 | 结论以“三、……”等正文小节开头，或是中段分析 | 在文末找真正的结语；没有就按下表处理 |
| 结论碎片 | 以 `，；、的而` 开头，或过短 | 回读 PDF 末尾重写；碎片比没有结论更误导 |
| 残留重字、错字 | 摘要开头出现重复字等 | 抽查首句；自动清洗不能保证零错字 |
| 占位文字 | “详见原文”“待补充” | 不是内容；重新提取或如实标注缺口 |

### 结语标题的多样性

不要假定结语一定叫“结语”或“结论”。实际遇到过：

- `四、结语`、`五、结论`、`五、结论与政策建议`、`余论`；
- `结　语`（两字之间是全角空格 U+3000）、`结\n语`（两字被拆到两行）；
- 没有独立结语：最后一段或最后一个理论小节承担结论功能；个别论文的提要本身就是结论性陈述。

找不到显式标记时，定位“（责任编辑”“（收稿”之前的最后实质段落。没有独立结语而由摄入者整理的结论，要注明“根据原文整理，非逐字摘录”。

## 四、外科式替换

修复单个章节时只替换该章节，保留其余内容：

```python
import re
pattern = r'(## 主要结论\n)([\s\S]*?)(\n## |\Z)'
m = re.search(pattern, content)
new_content = content[:m.start(2)] + new_text + content[m.end(2):]
```

- 新文本先写入临时文件再读回，避免在脚本字面量里处理大段中文标点；
- 替换后检查：目标章节长度与开头、全部二级标题仍在、其他章节未变；
- 只更新实际修改页的 `updated`，并追加日志。

## 五、YAML 与格式

- frontmatter 的引号问题以**真实解析结果**为准：典型错误是值里嵌套双引号或以双引号开头未闭合；中文弯引号本身是合法标点，不会让 YAML 解析失败，不要为了“看着干净”删除原文中的有效标点与术语。确需引号时用单引号包裹。
- 每个 `## 标题` 后空一行。批量写入（尤其由子代理写入）后统一规范：`re.sub(r'(## [^\n]+)\n(?=[^\n#])', r'\1\n\n', content)`。
- 每次修改 frontmatter 后立即重新解析 YAML，并看 diff（多一个前导空格就可能改变结构）。

## 六、质量基准与一次性验收

用一页已验收的论文页作为基准，把其他页面提升到同一水平。下表是**筛查信号**（按项目调整），不作验收门槛——合格与否以“原文覆盖＋具体证据”为准：

| 维度 | 标准 |
|---|---|
| 摘要 | 对照原文完整；外文术语与合法标点保留，不按“纯中文”机械删改；50 字等长度只作信号 |
| 主要结论 | 以完整句开头、确为作者结论；长度只作信号（长结论也可能取错章节） |
| PDF 残留 | 无 `］［】【`、页码、私用区字符、断行 |
| 关键词 | 干净、分隔统一、无换行 |
| YAML | 用解析器真实解析通过；防的是嵌套／未闭合引号，不误伤合法标点 |
| 章节格式 | 每个 `## 标题` 后有空行 |

长度与数量都只是信号：长结论也可能取错章节；短篇批复、无独立结语的论文按实际内容如实表达。**六个维度一次性全部检查**后再报告“完成”；不要修完一项就宣布完成，让用户逐个发现下一项。

引用规范与引用案例章节的补全方法见 `legal-wiki-audit-repair` 技能的 `references/literature-audit-and-repair.md`（按技能名查找该技能）。

## 七、并行提取与子代理

篇数较多（如 15 篇以上）时可分批并行（每批 8—9 篇），由各批输出结构化 JSON，主流程统一写页面。宿主不支持子代理时串行分批执行。

- 子代理报告“完成”不等于产出存在：逐一核对每批负责的每个输出文件；
- 某批输出缺失时，直接用脚本补跑该批，比重新派发更快；
- 子代理常见失败：摘要取成英文、结论取成碎片、标题后无空行、写“提取受限”之类免责说明代替提取、因接口限流中途退出；
- 大段输出分块读取，避免终端输出被截断；
- 全部批次结束后，对**每个文件的内容**运行上表验收，而不是看批次状态。

## 八、页面体量参考

内容完整的论文实体页通常为数千字节；过薄（如 1,500 字节以下）的页面多半缺少论点或结论。体量只作筛查信号，不作验收标准，见 [content-completeness.md](content-completeness.md)。
