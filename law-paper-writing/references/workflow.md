# 论文工作流

## 任务路由

按 [任务入口](../SKILL.md) 选定的范围执行，不重新选择模式或加载全部流程。只完成当前任务需要的阶段；涉及完整正文时，必须先具备最低限度的研究问题、来源范围和引注方案。

## 一、建立项目卡

复制 `assets/templates/paper-project-brief.md`，记录主问题、初步结论、目标期刊、允许使用的资料、法律资料截止日期和交付格式。事实不足但不改变方向时可暂定；会影响结论或真实性时先询问。

## 二、诊断研究问题

依次回答：

1. 论文究竟要解释、评价或重构什么法律问题？
2. 现行规范、裁判或学说在哪里出现冲突、模糊或不足？
3. 现有研究已经解决什么，尚未解决什么？
4. 本文新增的是材料、解释、方法、分类、反例还是制度方案？
5. 哪些相邻问题明确不处理？
6. 现有材料足以支持多强的结论？

将“一篇论文一个问题”理解为“一个主问题统摄有限子问题”，不要把它变成拒绝复杂问题的口号。

需要判断研究增量或新框架能否成立时，按 [论证诊断](argumentation-diagnostics.md) 比较既有解释与本文主张；未读足相关文献时，将增量标为待验证，不能宣布填补空白。

## 三、整理材料

复制 `assets/templates/source-register.md`，为每份材料分配稳定来源编号，如 `S001`。至少记录：

- 完整来源信息；
- 原始文件、正式网页或数据库位置；
- 可引用的页码、条文、段落或案号；
- 摘要与原文摘录；
- 支持或反对的主张；
- `VERIFIED / PARTIAL / LEAD_ONLY / UNUSABLE` 状态。

优先阅读原文。只读到摘要、转述或二次数据库时，不得假装已经掌握原文。来源登记记录材料本身；论点—证据—引注表记录该来源如何支持具体主张，两者不得相互替代。

## 四、建立主张链

使用 `assets/templates/claim-evidence-matrix.md`，按以下顺序设计：

```text
主问题
→ 核心判断
→ 子问题
→ 分节主张
→ 证据与反方材料
→ 分节结论
→ 总结论
```

每节明确功能，不强制三至四节。结构可采用递进、并列、比较、历史演变、规范解释、案例归纳或混合方式。

结构诊断时，按需使用 [论点表的章节衔接记录](../assets/templates/claim-evidence-matrix.md) 说明各节输入、所得判断及下文用途；局部任务可直接用短段落说明。并列章节应共同回答主问题；递进章节应说明前节结论怎样支持后节，不能仅凭顺序或标题对称声称推理成立。

## 五、分节起草

起草前读取 [日常论证检查](argumentation-core.md)，以及 [正文表达](legal-prose.md)。按本节主张选用检查，不将全部检查项逐一写进论文；涉及比较法、法定要件重构、证明责任或实体程序衔接时，再运行相应的专项检查，不为通过清单增加无关章节。

段落通常承担一种或数种功能：提出判断、解释理由、提供证据、分析证据、处理反例、限定结论、连接下文。连续罗列法条、案例或作者观点而不分析，视为论证缺失。

根据读者此处需要理解的问题安排顺序：可以先提出判断再说明根据，也可以从材料或争议切入。每一步应交代它为何支持下一判断；单纯罗列材料、贴上概括或换用连接词，都不能补足缺失理由。相邻段落的篇幅和展开方式服从论证需要，不要求每段重复同一套结构。

起草时同步设置引注标识，不要等全文写完再凭记忆补脚注。若来源未定位，立即使用待核标记。

## 六、全文修改

至少分三轮：

1. **论证轮**：主问题、主张链、反方观点、证据充分性与结论边界；
2. **结构轮**：章节功能、段落顺序、重复内容、过渡与标题；
3. **表达轮**：按 [正文表达](legal-prose.md) 检查主体与条件、句段推进、术语和引文；核对改后立场强弱与原意，并精修摘要与关键词。

题目、摘要和引言可在正文稳定后精修，但是否在引言预告主要结论应服从论证需要与目标期刊惯例，不设统一禁令。

收到导师或审稿反馈时，按需使用 [反馈落实表](../assets/templates/revision-response.md) 记录原文位置、问题类型、实际修改和完成证据；单条意见可直接列出对应信息，不强制建表。按 [论证诊断](argumentation-diagnostics.md) 区分实质论证与表达问题；报告未落实项及原因，不能以删除意见或接受修订代替解决问题。改稿交付时附新旧稿继承说明：哪些沿用、哪些修改、哪些新增及其依据。

## 七、交付

交付时声明：

- 当前是工作稿还是最终稿；
- 使用了哪些资料范围；
- 法律和事实资料截止日期；
- 仍存在哪些待核或范围限制；
- 是否已经完成目标期刊适配；
- 本次交付的版本号与相对上一版的变化。

交付新版本必须升版本号并在交付说明中注明变化；旧版本保留，不静默覆盖。
