# 跨平台测试与本机检查配置

本次只调整测试及开发说明，生产脚本、技能规则、发布版本与文件锁不变。

## 论文—案例同步指纹

`expect_sha256` 的输入协议是使用 `--dry-run` 预演输出。脚本读取文本后统一换行并计算 UTF-8 文本指纹，因此不能用原始 CRLF 文件的字节哈希代替该指纹；纯换行风格变化不计为内容变化。

测试从真实预演取得指纹，分别覆盖 LF 与 CRLF：错误指纹拒绝且整库文件无写入；正确预演指纹允许同步并保留原字节备份；预演后真实内容变化拒绝且整库文件无写入。两类拒绝场景都检查冲突页位于计划首项和末项，防止前页被提前写入。没有修改或放宽生产脚本的指纹核对。

## 符号链接能力

真实链接用例仍实际调用 `Path.symlink_to()`。只有创建阶段明确返回 Windows `WinError 1314` 才将对应子场景标记为跳过；其他异常继续报错。可开启 Windows 开发者模式或使用具备链接权限的终端，也可在 Linux 测试环境运行真实场景；测试不会主动修改系统设置。

新增故障注入验证：权限不足只影响对应链接子场景，同一用例中的 Git worktree 与旧别名检查继续执行；其他错误不会被静默跳过。另以模拟链接识别覆盖技能目录、分类目录、状态父目录和发布目录的拒绝逻辑，验证拒绝时文件无变化。

模拟测试不等于真实文件系统测试。看到 `OK (skipped=...)` 只能说明已执行部分无失败；发布前须在具备能力的环境补跑真实链接场景并检查跳过列表。

## 本机私人词表

`tests/.project_terms.local.json` 是不入库的 JSON 字符串数组，由维护者填写实际需要排除的私人项目词。缺配置会明确跳过；空词表不能提供隐私验证。该检查仅覆盖三个技能中的指定文本文件，且有评测和更新器文件豁免，不替代整个仓库与提交历史的发布前隐私审查。
